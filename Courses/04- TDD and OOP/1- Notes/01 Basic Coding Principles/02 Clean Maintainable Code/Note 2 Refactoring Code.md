Refactoring code is when you restructure or improve working code to make it more maintainable and easier to read. Refactoring code is an important part of programming. You aren't finished solving a coding problem until you attempt to refactor it at least once. Even working code can almost always be improved on.

The first step to refactoring code is to have working code. Working code is better than no code at all. Working code means that it fits all the specifications for the implementation of the problem that the code is solving. Efficiency of the code is not necessary.

Then, after you have working code that solves the problem, you should go through your working code to see if there is anything that you can improve on to make it easier to read for other developers who may use your code.

Most developers use a set of guidelines or principles to aid them in refactoring their code to consistently write code that is easy to read and use for other developers. These guidelines may vary from company to company, but there are some principles that you will learn this week that will be useful no matter where you end up working.
